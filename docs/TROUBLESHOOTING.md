# 문제 해결

| 증상 | 원인·해결 |
|---|---|
| 사이드바에 "Claude Code를 찾지 못함" | 백엔드 프로세스의 PATH에 `claude`가 없다. `which claude` 확인, 또는 `AI_ORG_CLAUDE_BIN=/절대/경로/claude` |
| 응답이 `error`로 끝남 | 메시지의 오류 문구 확인. CLI 로그인 만료면 터미널에서 `claude` 실행 후 로그인. 서버 로그 확인 |
| 과금 방식이 예상과 다름 | `ANTHROPIC_API_KEY`가 환경에 있으면 CLI 로그인 대신 API 키를 쓴다. 서버를 띄우는 셸에서 `unset ANTHROPIC_API_KEY` |
| 응답이 "실행 대기 중(동시 실행 한도)"에서 멈춤 | 다른 실행이 한도(`AI_ORG_MAX_RUNS`, 기본 2)를 쓰는 중. 실행 패널에서 확인하고 필요하면 중지 |
| 매우 느림(라즈베리 파이) | 정상 범위: 단순 응답 수 초, 설계 담당 1~2분. 동시 실행 수를 줄이면 메모리 부족을 피한다 |
| 승인 요청이 안 보임 | 실시간 연결 상태(사이드바 아래) 확인. 커맨드 센터 실행 패널·대시보드 승인 목록은 REST로도 갱신된다 |
| 명령이 승인 없이 실행됨 | 그 에이전트 권한의 '실행 전에 내 승인 받기'에 해당 묶음이 있는지 확인. 프로젝트 `.claude/settings.json`의 allow 규칙은 Claude Code 단계에서만 적용되며 우리 훅은 그보다 먼저 판정한다 |
| `409 해당 에이전트가 아직 응답 중` | 같은 대화의 같은 에이전트는 동시에 한 턴만. 끝나길 기다리거나 중지 |
| 프로젝트 등록 `403` | 탐색 경로 밖이거나 심볼릭 링크가 밖을 가리킨다. 먼저 상위 폴더를 탐색 경로로 추가 |
| API `403 host/origin not allowed` | 다른 주소로 접속했다. `http://127.0.0.1:3000` 또는 `localhost:3000` 사용. 포트를 바꿨다면 `AI_ORG_WEB_PORT` 설정 |
| 포트 충돌 | `AI_ORG_PORT`, `AI_ORG_WEB_PORT`(Vite `strictPort`), 웹의 `AI_ORG_API_URL`을 함께 바꾼다 |
| 서버를 껐다 켰더니 응답이 '중단됨' | 의도된 복구 동작. 다시 생성으로 이어서 할 수 있다(세션은 resume) |
| 스키마 오류(열 없음) | 0.0.x는 마이그레이션이 없다. `~/.ai-org/ai-org.db`를 백업 후 삭제(DATABASE.md) |
| MCP 연결 점검이 'CLI 승인 대기' | 그 폴더에서 대화형 `claude`를 실행해 프로젝트 MCP 서버를 승인하면 사라진다. 이 앱의 에이전트 실행에는 영향 없음 |
| 에이전트가 MCP 도구를 못 씀 | 에이전트 설정에서 그 서버를 허용했는지, 연결 점검에서 '연결됨'인지 확인. 첫 실행은 `npx` 다운로드로 오래 걸릴 수 있다 |
| 사무실에 캐릭터가 없음 | 조직에 활성 에이전트가 있는지 확인. 브라우저 콘솔의 WebGL 오류 확인 |
