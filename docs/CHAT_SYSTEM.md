# 채팅 시스템

구현: 백엔드 `api/chat.py`, `services/runs.py`, `services/commands.py`, `services/attachments.py`, `services/prompting.py` /
웹 `features/command/{CommandCenter,Composer,Messages}.tsx`, `lib/live.ts`.

## 1. 구조

- **대화(Conversation)**: 조직 소속. 대상 `org`(CEO) · `team`(부서) · `agent`. 프로젝트 1개와 컨텍스트 목록을 가진다.
- **메시지(ChatMessage)**: `user` · `assistant`(에이전트별) · `command`(명령 결과). assistant는 `pending → streaming → done|error|interrupted`.
- **세션**: (대화, 에이전트)마다 Claude Code 세션 ID를 `agent_threads`에 저장하고 다음 턴에 resume한다.
- 제목은 첫 메시지 앞부분으로 정한다. 대화 목록에 실행 중 표시.

## 2. 대화 유형과 정책

| 유형 | 받는 에이전트 | 프롬프트 |
|---|---|---|
| CEO | 조직의 is_lead | 조직 구성 전체 + 위임 도구로 분배·취합(AGENT_ORCHESTRATION.md) |
| 팀 | 부서 대표 | 팀원 목록 + 팀 대표 응답 |
| 개별 | 그 에이전트 | 자기 역할·지침 |
| 조직 활동 | 실행 패널·대시보드 활동 | — |

모든 유형에서 각 에이전트 자신의 권한 정책이 적용된다.

## 3. 스트리밍

`message.delta`를 메시지 ID별로 화면에 누적하고, `message.completed`에서 서버 확정본으로 바꾼다. 마크다운(GFM)·코드 하이라이트
(highlight.js)·코드 복사·응답 복사·다시 생성(같은 질문으로 새 응답). 중지는 `/stop` 또는 입력창의 중지 버튼.

대기 메시지(응답 중인 에이전트에게 보낸 메시지, #45)에는 '수정'·'취소' 버튼이 있다(#95).
- 수정은 그 자리에서 편집한다: Ctrl/⌘+Enter 저장, Esc 취소. 멘션·첨부는 바뀌지 않는다. 빈 내용·바뀐 것 없음·50,000자 초과는 저장 전에 막는다.
- 고친 메시지에는 '수정됨'(마우스를 올리면 수정 시각)이 보인다. 고친 내용이 그대로 전달된다.
- 이미 전달·취소된 메시지는 고칠 수 없다. 편집 중에 전달·취소되면 편집이 닫히고, 입력하던 내용은 알림의 '내용 복사'로 클립보드에 담을 수 있다.
  저장 요청이 그사이 전달과 겹쳐 409를 받아도 같은 방식으로 닫힌다. 그 밖의 오류는 사유를 알리고 편집을 유지한다.

## 4. 파일 첨부

- 끌어놓기·파일 선택·붙여넣기. 최대 10개, 파일당 20MB. 고르는 즉시 업로드(진행률 표시), 이미지는 미리보기.
- 서버 검증: 확장자 허용 목록 + 매직 바이트(PNG/JPEG/GIF/WebP/PDF), 텍스트는 UTF-8·NUL 없음. 파일 이름 정리(경로 제거).
- 저장 `~/.ai-org/uploads/<id>/`(0600). 보내기 전은 초안(삭제 가능), 보내면 대화에 묶임(대화 삭제 시 함께 삭제).
  묶이지 않은 초안은 24시간 뒤 서버 시작 시 정리.
- **Claude Code 전달**: 내용을 프롬프트에 넣지 않는다. 첨부 폴더를 `add_dirs`로 허용하고 경로를 알려 Read 도구로 읽게 한다
  (Read는 텍스트·이미지·PDF를 읽는다). 브라우저는 로컬 파일 시스템에 접근하지 않는다.

## 5. 슬래시 명령(Command Registry)

`@command(name, description, usage, *Arg)`로 등록하고 `GET /commands`가 명세를 준다. 입력창은 `/`에서 자동완성·사용법을 보여 준다.

| 명령 | 동작 |
|---|---|
| `/help` | 명령 목록 |
| `/agents` | 구성원·상태 |
| `/delegate @에이전트 업무` | 작업 생성 + 그 에이전트 실행 |
| `/team 부서` | 대화 대상을 팀으로 |
| `/project 이름` | 대화에 프로젝트 연결 |
| `/tasks` | 작업 목록 |
| `/status` | 상태별 인원·실행·승인·작업 수 + 실행 중인 에이전트별 `실행 중: 이름` 행(상태 라벨, 에이전트당 1행) |
| `/stop` | 이 대화의 실행 중지 |
| `/approve` | 승인 대기 목록(실행 패널로 안내) |
| `/skills` | 찾은 Skills와 허용된 에이전트 |
| `/mcp` | 설정된 MCP 서버 |
| `/clear` | 같은 대상의 새 대화(이전 대화 보존) |

인자 해석: agent 인자는 첫 `@이름`, text 인자는 나머지 전체.

## 6. 멘션

`@`에서 에이전트 자동완성. 보낼 때 본문에 남은 `@이름`의 에이전트에게 각각 전달한다(대화 대상보다 우선). `@All`은 조직 전체 공지로 CEO에게.

## 7. 컨텍스트

종류: 프로젝트 경로(폴더·파일, 프로젝트 안만 — 트리 선택기), 에이전트 소개, 이전 작업 결과(최대 4000자), GitHub `owner/repo`(형식 검사),
Skill 정보. 저장 시와 **보낼 때마다** 서버가 다시 검증한다(프로젝트 밖·없는 경로·다른 조직 항목은 거부). 프롬프트에는 위치·요약만
`<context>` 블록으로 넣고, 내용은 에이전트가 자기 권한으로 읽는다. 헤더의 칩으로 현재 컨텍스트를 보이고 지울 수 있다.

## 8. 실행 패널

접을 수 있는 섹션: 승인 대기(허용·거부), 실행 중 에이전트(상태·최근 도구), 최근 도구 사용(실시간, 새로고침 시 비워짐), 작업.
진행률은 표시하지 않는다(Claude Code가 제공하지 않음). 승인 요청은 해당 대화의 입력창 위에도 뜬다.
