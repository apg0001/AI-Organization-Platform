# UI/UX 가이드라인

## 1. 화면 구조

```
┌ 사이드바 ───────┬ 본문 ──────────────────────────────┐
│ 조직 전환        │ 페이지 머리(제목·설명·주 행동)          │
│ 대시보드         │ 내용(섹션·표·목록·캔버스)               │
│ 커맨드 센터 (n)  │                                       │
│ 조직 · 사무실    │                                       │
│ 프로젝트 · 기능   │                                       │
│ ✦ 조직 설계      │                                       │
│ Claude Code 상태 │                                       │
│ 실시간 연결 상태  │                                       │
└─────────────────┴───────────────────────────────────────┘
```

- 사이드바 위 **조직 전환**이 운영 모드의 범위(현재 조직)를 정한다. 커맨드 센터 옆 숫자는 승인 대기 수(앰버).
- '조직 설계'는 설계 모드의 독립 작업 공간이라 따로 둔다.
- 사이드바 아래에 Claude Code 감지 상태와 실시간 연결 상태를 항상 보인다(점 + 글자).

## 2. 페이지별 목적과 원칙

| 페이지 | 질문 | 원칙 |
|---|---|---|
| 대시보드 | 지금 누가 무엇을? 나를 기다리는 것은? | 승인 → 실행 중 → 조직·프로젝트 → 작업·활동 순. 숫자 타일 대신 목록. 조직이 없으면 시작 안내 하나만 |
| 조직 설계 시작 | 어떻게 시작할까? | 세 진입점(AI·템플릿·직접). 템플릿은 미리보기 후 시작 |
| 설계 작업 공간 | 어떤 조직을 만들까? | 왼쪽 대화, 오른쪽 조직도, 노드를 누르면 설정 서랍. 적용 전에는 실제 조직이 바뀌지 않음을 계속 알린다 |
| 커맨드 센터 | 누구에게 무엇을 맡기고, 지금 어떻게 되고 있나? | 대화 목록 · 채팅 · 실행 패널(접기). 헤더에 대상·프로젝트·컨텍스트 |
| 조직 | 조직이 어떻게 생겼고 지금 상태는? | 운영 조직도는 구성 읽기 전용(수정은 설계 초안으로), 구성원 표, 권한 탭(권한 표·프리셋 — 바로 저장), 변경 이력. 조직도 노드에 권한 배지와 프리셋 메뉴 |
| 에이전트 상세 | 이 사람은 누구이고 무엇을 할 수 있나? | 개요(역할·작업·실행 환경) / 설정·권한(즉시 저장, 권한을 넓히는 변경은 확인 창) |
| 프로젝트 | 에이전트가 어디서 일하나? | 등록 목록 + 찾은 후보 + 탐색 경로. 등록 해제는 파일을 지우지 않음을 명시 |
| 기능 관리 | 이 컴퓨터에 어떤 도구가 있고 누가 쓰나? | 종류별 탭, 허용된 에이전트, 미구현(MCP 실행 연결) 명시 |
| 사무실 | 조직이 살아 움직이나? | 지도 전체 화면, 캐릭터 클릭 → 상세, 구역 안내 |

## 3. 사용자 흐름

1. 첫 실행: 대시보드 빈 상태 → 조직 설계 → (AI 대화 또는 템플릿) → 검토 → 생성 → 조직 화면.
2. 첫 업무: 커맨드 센터 → 대화 시작(CEO) → 메시지 → 스트리밍 응답 → 필요 시 승인.
3. 위임: `/delegate @에이전트 업무` → 실행 패널 작업 → 결과를 다른 대화의 컨텍스트로.
4. 조직 변경: 조직 → 조직 수정 → 설계 작업 공간 → 검토 → 적용(실행 중이면 확인) → 이력.

## 4. 정보 계층

제목(lg 600) → 섹션 제목(sm 600 + 구분선) → 본문(base) → 메타(xs faint). 한 화면의 주 행동(primary 버튼)은 하나.

## 5. 반응형

데스크톱 우선(1280px 이상에서 3열). 1280px 미만: 커맨드 센터 실행 패널 숨김. 1024px 미만: 설계 작업 공간은 대화 위·조직도 아래로 쌓임.
768px 미만: 사이드바 아이콘만. 모든 주요 기능은 좁은 창에서도 접근 가능해야 한다(실행 패널 정보는 대시보드·승인 배너로 대체).

## 6. 인터랙션

- 키보드: 채팅 Enter 전송·Shift+Enter 줄바꿈, 한글 조합 중 Enter 무시, 자동완성 ↑↓·Tab·Enter·Esc, 조직도 Delete로 선택한 연결 삭제.
- 낙관적 반영: 설계 명세 편집은 즉시 그리고 서버 검증 실패 시 되돌리며 토스트로 알린다.
- 위험 동작: 조직 적용은 검토 대화상자, 실행 중 적용은 추가 확인. 등록 해제처럼 되돌릴 수 있는 동작은 즉시.
- 토스트는 결과 알림에만(성공·실패), 오류는 무엇이 잘못됐고 어떻게 고칠지 쓴다.

## 7. 접근성

- 상태 = 아이콘 + 글자 + 색. compact 표시는 sr-only 글자.
- 모든 컨트롤은 라벨(`Field`가 id 연결) 또는 aria-label. 아이콘 버튼은 `IconButton`.
- `:focus-visible` 링, 본문 건너뛰기 링크, 실시간 영역 `aria-live="polite"`(채팅·설계 대화), 오류 `role="alert"`.
- 대비: §DESIGN_SYSTEM 표. 줄인 모션 존중.

## 8. 로딩·빈·오류 상태

- 로딩: `LoadingState`(스피너 + "불러오는 중…"). 실행 대기·생각 중은 메시지 자리에서 표시.
- 빈 상태: `EmptyState` — 무엇이 없는지 + 다음 행동 하나.
- 오류: `ErrorState`(메시지 + 다시 시도). 실행 오류는 메시지 안에, 정책 거부는 도구 목록에 '거부·실패'.
- 미구현: 버튼을 만들지 않는다. 필요한 곳에는 "Phase N에서 구현" 문구로 밝힌다.
