# 에이전트 오케스트레이션

## 현재 구현(Phase 3 수준)

| 기능 | 동작 | 상태 |
|---|---|---|
| CEO 대화 | 조직 대상 대화는 CEO(is_lead)에게 간다. 시스템 프롬프트에 조직 구성(이름·직책·부서·보고 대상·역할)을 넣고, 분배 계획을 제시하게 한다 | Tested |
| 팀 대화 | 부서 대표(상위 관리자가 부서 밖인 첫 구성원)가 팀원 목록을 받고 팀을 대표해 답한다 | Tested |
| 직접 대화·멘션 | `@이름`이 있으면 그 에이전트들에게 각각 전달(병렬, 동시 실행 한도 내) | Tested |
| @All | 조직 전체 공지로 표시해 CEO에게 전달 | Tested |
| 수동 위임 | `/delegate @에이전트 업무` → `Task(running)` 생성 → 그 에이전트 실행 → 결과·상태를 작업에 기록 | Tested |
| 결과 재사용 | 완료 작업 결과를 다른 대화의 컨텍스트로 첨부 | Tested |
| 상태 | idle → thinking → working(도구 사용 중) → waiting(승인) → completed/failed | Tested |

CEO는 아직 **스스로 다른 에이전트에게 일을 넘기지 못한다**. 프롬프트가 이를 밝히고, 필요한 위임을 `/delegate` 명령으로 제안하게 한다.

## Phase 5 설계(Planned)

목표 흐름: 사용자 → CEO → 부서장 → 담당자 → 보고 → CEO 취합 → 사용자.

1. **위임 도구**: 위임 권한(`can_delegate`)이 있는 에이전트에게 인프로세스 MCP 서버(`create_sdk_mcp_server`)의 도구를 준다.
   - `delegate_task(assignee, title, brief, depends_on?)` — 조직도 규칙 검사(하위 또는 협업 관계 대상만), Task 생성, 실행 예약.
   - `request_review(reviewer, task_id, note)` — 검토 요청(협업 kind=review).
   - `report_result(task_id, summary)` — 상위 관리자에게 보고.
   도구 호출도 PreToolUse 정책을 거치며 `delegate` 묶음 승인을 걸 수 있다.
2. **작업 트리**: `Task.parent_id`로 위임 트리, `depends_on`으로 선행 작업. 스케줄러는 선행이 끝난 작업만 실행하고 동시 실행 한도를 지킨다.
3. **보고**: 하위 작업이 모두 끝나면 위임자에게 결과 요약을 새 턴으로 전달(resume)해 취합하게 한다.
4. **검토·재작업**: 검토자가 거절하면 원 담당자에게 사유와 함께 재작업 작업을 만든다(최대 횟수 제한).
5. **실패 처리**: 실패 작업은 위임자에게 보고되고 재시도·재배정·사용자 개입을 결정한다.
6. **사용자 개입**: 전체 중지(`/stop` 조직 범위), 특정 에이전트에 추가 지시(그 에이전트 대화), 중요한 작업 승인(plan 승인 정책).
7. **가시성**: 에이전트 간 메시지를 `ChatMessage(role=system)`와 활동 이벤트로 기록하고 사무실에서 '업무 전달' 애니메이션으로 보인다.

결정 이유: Agent Teams는 실험 기능이며 SDK 실행에서 팀원이 생성되지 않고 권한 분리가 약해(ADR-005) 자체 오케스트레이터를 둔다.
